# F01 部署复核与试点路径

## 现场场景与责任

拟服务对象为保留安卓离线工具的小型设备维护班组。设备换新时，班组保有 APK 和操作规程，原工程或维护人暂时不可用。试点先使用合成巡检单。操作员提供南线、北线及冷启动期望，维护员确定目标设备和数据备份，复核员在隔离环境核对操作与差异后交付 APK。出现换签冲突、包与设备 ABI 不匹配或关键操作失败时，先记录原因并保留旧终端和原 APK。

## 首次安装与复测的记录项

| 验证场景 | 需记录的证据 |
|---|---|
| 干净 Windows 安装 | Windows 版本、程序构建号与包 SHA-256、安装与卸载退出码、无 Python/SDK 路径时的自检、正确输入和篡改候选的校验结果。 |
| 首次准备运行环境 | 目标 API、已存在与下载的组件、下载字节、缓存占用、耗时、网络失败后的恢复情况、模拟器是否成功启动。 |
| 断网复跑 | 从同一基准、候选和报告开始，记录安装哈希、实际 ABI、冷启动复测步骤及每个目标结果。 |
| 非开发者试用 | 由未参与开发者按同一指南独立完成，记录完成用时、人工操作次数、卡点及是否需要协助。 |

干净 Windows 的安装校验与 Android 的实机功能复测分开记账。验收报告中的设备类别、系统版本和 ABI 决定结论适用范围。首次准备可能需要系统镜像、平台工具、模拟器、构建工具和 Java，按所选系统获取；功能回编另外依赖 Apktool。试点机器建议先用当前安装包实测资源占用，再决定现场断网所需的缓存和存储。

## 拟定路线

| 阶段 | 交付边界 | 下一阶段入口 |
|---|---|---|
| 第 1 年，复核原型 | 公开自有用例、拒绝用例、候选与差异。固定对照下测完成率、重试次数、用时和模型费用。 | 主案例可由评审独立复跑，失败能够追溯。 |
| 第 2 年，小规模试点 | 与有授权的维护班组选择可脱离生产数据的离线应用。验证设备更新、数据迁移与回滚。 | 有实操记录、受影响功能清单和回滚演练。 |
| 第 3 年，扩展场景 | 支持常见业务框架的界面测试与更多 ABI/设备，建立外部权限和签名变化的人工审查流程。 | 新样本使用相同的交付和复测门槛，并有失败分类。 |
| 第 4 至 5 年，持续维护 | 建立可重放案例库、工具链锁定与独立团队复核，按实际试点结果决定扩展范围。 | 量化收益基于现场对照，报告成功、超时及不适用的任务。 |

衡量指标包括从拿到 APK 到完成关键流程验收的用时、人工操作次数、保留的业务行为和失败后恢复用时。现场成本还包含首次运行环境下载、存储与可选模型调用。当前巡检案例是模拟场景，现场试点记录由后续实际参与者提供。
