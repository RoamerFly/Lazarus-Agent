# v0.6.22 文件交接候选外部调用预审

三份候选在 Android 16 x86_64 通过应用内五步，并回读设备安装 APK 哈希。编译差异均保留原导出的接收页，同时增加了只读、非导出的 Provider。接收页仍会在本应用上下文中处理外部 Intent，因此要单独核对外部应用提交同一 URI 后的结果。三份候选当前排除出可分发样本。

| 轮次 | 候选与设备安装 SHA-256 | 编译差异 |
| --- | --- | --- |
| P06-agent-1 | `53ebd697f725b6b79c6e8f1f597756f2b3e2c81ecbc21941152f7c412bcfd300` | 新增 `.RecordProvider`，允许 URI 授权。发送显式指向原接收页，接收仍依据固定 URI 读取。 |
| P06-agent-2 | `baa651bd7a6f57ac6417123b090e88137db6ecd052810c66ca88506409858a92` | 新增 `.RecordFileProvider`，只读且限制私有文件路径。原接收读取分支保留。 |
| P06-agent-3 | `50ead99e8ba4d9bdab7a0015d547c42e740e5bf4d380b398403bee0b1a98b0ed` | 新增只读 `.RecordProvider`，接收页仍导出，按 `/record` URI 读取真实记录。 |

探针可在刚安装的同一候选上先发送已知 URI，再执行正常应用内写入和分享，最后从同一外部 UID 发送同一 URI。报告分别保存写入前界面、应用内步骤及写入后界面，并核对两个安装包的哈希和不同的 UID。

    python tools/replay_record_caller.py --apk <留档候选.apk> --sha256 <对应候选 SHA-256> --uri-before-and-after-share --out build/record-caller-before-after

默认路径为 `/record.txt`。第三轮复测追加 `--record-path /record`。前后对照已通过测试替身验证执行顺序，真实设备探针已排入专用模拟器的复测日程。应用内五步、编译差异和外部探针结果分别归档。[历史 URI 探针](0.6.21-context-history-focused.md)
