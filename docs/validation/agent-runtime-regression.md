# 设备诊断改进的两项开发回归

本轮使用开发提交 `e677c45`、DeepSeek Flash 和 Android 16 API 36 x86_64 专用模拟器。按 P1B 的原请求、验收步骤和构建额度复跑两个已见任务。共记录 12 轮终态，对照和模型试验一并保留。[逐轮记录](agent-runtime-regression.json)

| 用例 | Agent | 无语义改动回编 | 既有规则 | 同模型一次构建 |
| --- | ---: | ---: | ---: | ---: |
| P01 离线巡检单 | 3/3 | 0/1 | 0/1 | 1/1 |
| P02 归档阅读器 | 2/3 | 0/1 | 1/1 | 1/1 |

巡检单三轮各构建一次，候选均通过 10 步固定验收。原包在目标系统安装失败。三轮均直接通过 APK 内容分析并修改，没有调用原包复现工具。

归档阅读器三轮均调用原包复现，获得目标系统列有 `org.apache.http.legacy` 的证据。第一轮仍改写读取路径，候选出现 `VerifyError`，构建四次后达到执行上限，未导出候选，按固定计分口径列为未观测。第二轮替换类实现，通过固定界面检查。第三轮新增合成归档资产并通过固定界面检查。原样本只有构造固定协议版本的代码，未附原始归档文件。这些轮次验证目标设备上的行为，实际归档数据恢复需要另有样本。

已核对每份候选文件、独立报告和设备安装回读的哈希，并逐轮比对原包和候选所用的步骤。两项任务的同模型一次构建对照均通过。本轮与 P1B 的统计分别保存，本轮受测提交早于候选预检和系统库声明工具的加入。
