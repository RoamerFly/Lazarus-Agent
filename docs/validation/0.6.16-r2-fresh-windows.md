# r2 评审复测入口的干净 Windows 验证

GitHub 托管 Windows runner 从 r2 复核包恢复 14 份逐文件校验的输入，包括原下载脚本、原复测脚本、更新清单及签名，以及巡检单、矛盾断言和温度卡三组样本。原 ZIP 的 SHA-256 为 `45a134425fbf5056a328769d840bfc6608d9d04b71ec84f0bc4075f41c7ffead`。完整 ZIP 的文件和链接核验另在本地完成。[固定输入](0.6.16-r2-handoff-inputs.json) · [运行记录](https://github.com/RoamerFly/Lazarus-Agent/actions/runs/42100357421)

Windows PowerShell 5.1 执行包内脚本，从正式发布地址下载安装器并核对 SHA-256。随后在全新的按用户安装目录安装 v0.6.16。存储和临时目录均含中文及空格。Android 16 环境从未就绪到可运行用时约 81 秒，占用约 6.38 GiB，再次准备时直接复用。[正式发布校验](0.6.16-release-publication.json)

复测阶段限制程序、Java、ADB 和模拟器的 Internet 出站，保留本机通信。包内复测脚本通过默认安装位置启动正式 EXE。三组报告的目标系统、预先固定的断言、原包和设备安装哈希均与 r2 对应。

| 样本 | Android 16 x86_64 结果 |
|---|---|
| 工作台演示巡检单 | 10 步行为通过，包含路线切换和两次冷启动。 |
| N03 矛盾断言 | 安装与启动通过，两条行为断言一过一败，报告为 `incomplete`。 |
| P1C 仓库温度卡 | 16 步行为通过，覆盖输入、单位换算和冷启动后的单位设置。 |

复测属于机器执行，非开发者试用记录仍待采集。[机器可读回执](0.6.16-r2-fresh-windows.json)

使用已核验的 r2 ZIP 可在交付分支重新触发同一流程。

```powershell
python -X utf8 tools/prepare_review_handoff_probe.py --pack '完整路径下的 r2 复核包.zip' |
  gh workflow run fresh-runtime-windows.yml --repo RoamerFly/Lazarus-Agent --ref delivery/f01-0.6.16 --json
```
