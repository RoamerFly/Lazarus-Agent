# F01 独立候选验收验证

通用 Agent 生成候选后，工作台使用提交时固定的步骤独立验收。它重新安装基准和候选，核对安装包哈希，只在目标应用自身的界面中识别控件和结果。原版已通过时单独标明。模型说明不参与通过判定。工作台分别显示签名构建、安装启动、功能验收，并为通过全部目标的功能候选提供单独的下载入口。

## Android 16 实测

输入为自制的 Tea Timer 样本。脚本固定模型工具响应，让模型两轮都声称成功。文件修改、Apktool 回编、签名、ADB 安装、界面观察和 HTTP 请求实际执行。该试验验证独立验收与下载门禁，真实模型的能力另见 [v0.6.6 验证报告](0.6.6-general-agent.md)。

| 检查 | 观测结果 | 下载 |
|---|---|---|
| 正例，点击两次后分别期待 `Field batch 1 active` 与 `Field batch 2 active` | 基准未达到预期，候选四步通过，下载件与设备安装包 SHA-256 一致 | 已验收入口 HTTP 200 |
| 反例，把第二次预期改为不存在的文字 | 候选正常安装启动并通过前三步，第四步失败 | 试验入口 HTTP 200，已验收入口 HTTP 409 |
| 重新运行正例报告 | 命令行只用原包、候选 APK 与报告复测，模型未参与，四步再次通过 | 返回码 0 |

本轮使用 Android 16 API 36 专用 x86_64 模拟器。正例候选 SHA-256 为 `b8242e2424e25336610623cb33b5cc4b996791e88be5cb32508487f8def26298`。ADB 回读与下载文件一致。对原包与该候选运行真实清单解析，权限及组件显式声明无变动，两份 APK 的签名证书指纹不同。原始工作台记录、两轮候选、独立复测报告和浏览器截图保存在本机的 `build/f01-review/p0/`，不随 Git 提交。

## 回归边界

浏览器确认两类下载标签、逐系统状态和报告入口，并从正常对话表单提交多步计划。单元测试覆盖错误预期、来自其他应用的同名控件、两个目标仅一个通过和设备安装包哈希不一致。真实 Android 14 / 15 联合复测尚待完成。当前工作是 P0 的产品与验收基线，P1 跨应用正式评测仍未开始。
