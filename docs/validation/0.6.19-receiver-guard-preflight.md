# v0.6.19 接收方授权回编检查与首轮专项

首个签名候选对应源码 `6de9491`。回编检查识别直线 smali 中可判定的新增授权路径，包括本包命名空间的动作与内容 URI、确定的读取或写入授权标志，以及未限定接收方的直接启动。检查将错误和所在方法返回给模型，拦截发生在实际回编计次之前。已有路径、显式接收目标和系统分享面板继续通过这项检查。动态 URI、跨方法及分支等无法判定的路径仍需设备及语义复核。

从 v0.6.18 正式评审包取出已在设备上复现风险的两份编译 APK，把相应方法送入新版回编入口。此前被探针读取的隐式发送路径被拒绝，限定本包的路径进入构建器。本项核对回编入口，实际设备效果见对照记录。[v0.6.18 竞争接收方复测](0.6.18-intent-boundary.md)

## 干净 Windows 复测差异

首个签名候选的安装器和固定 APK 复测通过。关闭模型从原包修复的首次运行中，原包按系统门槛拒绝安装，候选安装和启动通过。操作后先出现 System UI 无响应提示，随后出现旧应用提示，验收记录为证据不足。同一签名构建的第二台干净 Windows 通过该检查。[失败记录](https://github.com/RoamerFly/Lazarus-Agent/actions/runs/42139475774) · [同构建复跑](https://github.com/RoamerFly/Lazarus-Agent/actions/runs/42140549470)

修订源码 `c812e5b` 将旧应用提示的单次确认覆盖到操作后的观察阶段。对两轮 Windows 已保存的界面树做组合回放，原操作只执行一次，两个系统提示各处理一次，最终根据真实目标界面通过。这个组合回放使用模拟的 ADB 传输。修订签名构建和全组 42 轮评测另行核对。[修订签名构建](https://github.com/RoamerFly/Lazarus-Agent/actions/runs/42140825598)
