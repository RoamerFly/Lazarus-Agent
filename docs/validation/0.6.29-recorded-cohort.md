# v0.6.29 冻结批次的离线工具重放

在 Android 16 API 36 x86_64 专用模拟器上，使用 v0.6.29 对应的源码提交 `0e95b5f`，按 [P1C 冻结方案](../science-superpowers/preregistrations/2026-11-06-f01-p1c.md) 重跑六个正例、三个反例及三类对照，共 42 轮。脚本校验原 APK、冻结方案和历史逐轮结果的 SHA-256，写入试验计划后从原包逐轮重建。运行入口使用候选源码的评测器，便携 EXE 哈希用于绑定发布构建。EXE 图形界面操作另有 [同版工作台实测](0.6.29-packaged-workbench.md)。

Agent 和一次构建对照使用历史工具调用及原参数，按每批最多两次调用送入执行器。存档只保留调用顺序，因此复跑分批方式是固定的工程设置。本地规则和无语义改动回编使用原评测器执行。所有轮次都记录有无候选、构建次数、安装与行为结果，已安装候选由独立验收回读设备 APK 哈希。工具顺序及参数是否一致、工具成功状态是否一致分列统计。该批次调用真实模型零次，用于验证工具执行和设备验收的版本回归。模型独立分析与首次见到用例时的表现见 [历史 P1C](f01-p1c/report.md)。

## 首个完成的用例

P01 巡检单六轮已结束。三次 Agent 轨迹均生成新 APK，候选安装和启动均成功，独立验收共通过 30 个设备步骤。首次启动显示北线，两次冷启动分别恢复用户选择的南线和北线，对应的原巡检内容仍可见。三个原版均无法安装。三个候选哈希均和设备回读一致。

| P01 工作流 | 构建及 Android 16 观察 | 功能通过 |
| --- | --- | --- |
| Agent 历史轨迹 | 三轮构建产物通过安装、启动及行为断言 | 3/3 |
| 无语义改动回编 | 生成 APK，安装失败 | 0/1 |
| 本地规则 | 生成 APK，安装和启动通过，冷启动断言失败 | 0/1 |
| 一次构建 | 完成一次构建尝试，未生成候选 | 0/1 |

三个 Agent 轮次均重放了完整工具参数序列。前两轮的个别编辑返回值与历史不同，差异涉及文件哈希校验。第三轮的工具成功状态序列也一致。差异文件显示，前两轮使用应用私有首选项保存当前路线，第三轮还保留了失败的首选项调用及应用私有文件回退。这份检查点记录设备行为及修改路径，候选差异不代表发布推荐。其余 36 轮继续按同一冻结计划执行。[P01 逐轮回执](0.6.29-recorded-cohort-p01.json)

## 复跑入口

准备干净的候选源码检出、其 `dist/Lazarus-Agent.exe` 与 `build/local-exe-selftest-receipt.json`，以及 Android 16 专用实验室。仓库附 30 份轨迹的 536 次工具调用。每个调用只保留工具、参数及历史成功状态，同时保留每份原始轨迹的 SHA-256。该输入经过哈希校验，生成的 42 轮计划与使用本机原始档案时一致。[可复用的冻结输入](f01-p1c/replay-input.json)

在包含本报告的检出目录执行下列命令，路径替换为实际候选源码检出。输出目录应在候选源码的 `build` 下。可追加 `--check-only`，只校验输入并打印计划。

    python -X utf8 tools/replay_f01_recorded_cohort.py --checkout <候选源码目录> --output <候选源码目录>/build/f01-recorded-cohort

持有原始档案的复核者可追加 `--historical-trials <历史P1C原始目录>`。该目录须包含各试验的 `result.json`，其中 Agent 和一次构建轮次另须包含 `agent-trace.json`。

`plan.json` 固定构建、协议、试验清单和归档身份。`cohort.json` 随终态更新，每轮含原始结果与独立验收哈希。中途停止时，未完成目录保留供检查。已结束轮次和未观察轮次均保留在原计划分母。
