# 桌面运行反馈与 APK 导入改进

验证日期：2026-11-24。

## 运行结果

原有界面将设备操作结束后的 `ready` 一律显示为绿色“就绪”。Sensor Readout 2.4 在 Android 16 上被默认安装策略拒绝时，这会造成安装成功的错觉，并继续展示模拟器桌面。

现在主界面与运行记录顶部均展示结果卡片：安装或启动失败为红色，已观察到应用窗口的安装、启动通过为绿色，进行中为蓝色，尚待确认或验收为黄色。功能通过只用于独立功能验收通过的候选。完成一次操作不等于通过验证。

失败时隐藏设备截图并禁用设备交互。记录本轮测试起始位置，避免新任务沿用上轮成功状态。运行记录与错误详情仍可查看。

## 导入

桌面选择器默认打开 EXE 同级 `old_apk`，目录不存在时创建。开发态对应项目根目录下的 `old_apk`。只允许选择一个 APK；取消选择保留当前任务。原生选择器通过现有本机鉴权导入路由上传，不增加任意本地路径读取接口。

支持向工作台拖入单个 APK，显示拖入提示，拒绝多文件和非 APK，任务执行期间阻止重复导入。浏览器仍保留标准文件选择器，默认目录能力属于桌面原生选择器。

## 验证证据与范围

- Python 回归：194 项通过；原有重复 ZIP 条目测试产生 1 条预期警告。
- Node 状态测试：6 项通过，覆盖安装拒绝、崩溃、错误窗口、启动通过、旧结果隔离与功能验收状态。
- 读取当前工作台 Sensor Readout 任务的真实结果，状态解释器判定为红色“原包安装失败”，禁止预览。原始安装记录保持不变。
- 无头 Edge 集成：加载实际 HTML、CSS、JavaScript，模拟 API 返回安装失败及启动通过，检查结果颜色语义、失败截图隐藏、文件输入、拖入合法/非法文件及桌面桥调用。1280×720、1440×900、1920×1080 无整页溢出。API 模拟不代表 APK 已修复。
- 真实导入链：原生选择动作以测试替身返回 Sensor Readout 2.4 路径，实际调用本地服务器鉴权、上传、签名检查及分析，识别 `de.onyxbits.sensorreadout`，目标 API 36。未自动操作系统文件对话框。
- 新构建 EXE 以 `--self-test --self-test-report` 受控验证，不打开主窗口。保留正在运行的旧会话，新程序需关闭旧窗口后重新打开。

本地证据位于 `build/ui-feedback/`、`build/desktop-import-live-receipt.json`、`build/desktop-feedback-selftest.json`。本轮没有模型调用，没有修改或重新验证样本 APK 的 Android 行为。
