# v0.6.26 Flash 文件交接专项

在已见的自有归档阅读器夹具上增加了外部调用约束。开始前固定请求、五步行为验收、Android 16 x86_64 和另一 UID 的复测。实际只执行一次 `deepseek-flash` 试验，共 17 次请求和 1 次构建，低于 20 次请求上限。服务方用量记录 245,987 个输入 token，其中 234,624 个命中缓存。输出为 13,783 个 token。[固定计划](0.6.26-flash-private-handoff-plan.json)

| 环节 | 实际结果 |
| --- | --- |
| 原包 | Android 16 默认安装失败，原因是目标 SDK 22 低于安装门槛 |
| 候选构建、安装与启动 | 签名构建成功，安装与启动通过，设备安装哈希与候选一致 |
| 应用内交接 | 5/5，通过点击、`Shared`、冷启动与再次交接 |
| 独立应用调用 | 记录写入前后的同一探针地址和写入后伪造字节均显示目标应用的 `Rejected`，探针与目标应用的 UID 不同 |

差异复核表明文件编辑集中在原接收页面的 smali。发送端使用显式内部交接与进程内随机令牌，接收端先验证令牌，再读应用私有文件并检查字节。发布清单的权限、组件及共享库声明无差异。此候选没有公开记录 URI，外部测试使用预设探针地址。设备结果覆盖该页面收到的这三次外部请求。

专项复测包含自有原包、候选、五步报告、独立探针与差异，另外交付可直接试用的签名 APK。解压后 Windows PowerShell 5.1 核对 12 个登记文件，同版 EXE 通过样本输入校验，并在专用模拟器再次通过五步。外部调用的复跑入口是 `tools/replay_record_caller.py`，使用 `--uri-before-and-after-share --forged-bytes-after-share`。该结果归为开发专项，和 42 轮全组评测分别统计。
