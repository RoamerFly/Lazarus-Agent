## 两个失败

P01 第二轮成功构建并做过模型自己的设备测试，之后为消除系统旧版提示追加不必要的 SDK 改动。模型把 SDK 属性写到 Manifest 根节点，并在恢复后耗尽构建额度，最终返回 blocked。该轮没有发布候选，继续计失败。

P02 第二轮新增归档读取逻辑，模型自己的设备测试发现解析失败。多次修订后构建额度耗尽，最终返回 blocked。它没有被计入通过。

后续工程修正包括按文件哈希找回先前成功构建、提示模型收敛到用户目标，以及在回编前指出 SDK 声明的实际位置。修正已在 v0.6.8 源码中实现。后续实测和回归另列，原冻结结果保持。

## 差异复查

开发助理对 16 份通过候选的修改位置、资源或方法、权限和组件差异做了代码复查，并重新核对包内输入输出哈希与报告。此复查由 AI 辅助完成，非开发者及第三方的独立试用记录仍待补充。

| 用例 | 复查结论和适用范围 |
|---|---|
| P01，两份 | 路线选择参数写入 SharedPreferences，启动从同一键读取。保留南北线说明和切换分支。两份均无新增权限或组件。 |
| P02，两份 | 候选新增本地合成归档，从首行解析协议字段；没有直接把成功文本写入界面。原工程样本本身以固定协议对象模拟旧依赖，候选补充的归档内容为合成数据。结果只覆盖此受控路径，不能代表真实客户归档迁移。 |
| P03，三份 | 仅修改默认字符串的按钮及带数字占位符的状态文本。计数调用与格式化参数保留，未找到其他语言目录覆盖。 |
| P04，三份 | 修改三个字符串，点击监听和冷启动恢复初始标题的原逻辑保留。 |
| P05，三份 | 在原文件打开方法保存实际参数，启动读取同一参数。原资产内容及读取正文的路径保留，使用 apply 或 commit 写入本地配置。 |
| P06，三份 | 新增未导出的 ContentProvider，使用 content URI 及只读文件描述符交接记录。原接收逻辑仍实际读取首字节后决定显示 Shared。没有全局关闭文件 URI 检查，也没有新增权限。组件变化在报告中明确列出。 |

本次复查未扣减自动通过数。其覆盖范围是固定步骤与可读差异。未测试复杂业务数据、多用户、恶意 URI、其他外部接收应用或真实现场流程。
