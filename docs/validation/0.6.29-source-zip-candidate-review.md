# v0.6.29 r3 通过候选的改动复核

范围为 r3 源码 ZIP 复跑中通过设备行为验收的 21 份正例候选，包括 17 份 Agent 轨迹、2 份规则和 2 份一次构建对照。用原 APK、候选 APK、设备安装回读、验收报告和留档差异的哈希建立逐份对应。用 Android 构建工具重新读取编译后清单，并逐个比较 APK 的 `assets/` 文件。21 份候选均无权限增删，资产文件内容一致。[逐份回执](0.6.29-source-zip-candidate-review.json) · [原始批次的逐轮审核](0.6.29-source-zip-cohort-audit.json)

| 用例 | 通过候选的改动及适用范围 |
| --- | --- |
| P01 巡检单 | 三份候选根据用户选择保存路线，冷启动恢复原有清单。前两份使用私有首选项。第三份还包含无效接口调用、宽泛捕获和私有文件回退。 |
| P02 归档阅读器 | 三份 Agent 候选在编译清单中把旧 HTTP 共享库声明为可选。规则对照省略 `required`，按默认值要求设备提供该库。四份候选均在实际提供此库的 Android 16 镜像上通过原有操作。[Android 共享库声明](https://developer.android.com/guide/topics/manifest/uses-library-element) |
| P03 泡茶计时器 | 三份 Agent 候选和一次构建对照均只替换两项资源，保留计数占位符。 |
| P04 温度卡 | 三份候选从运行时输入计算华氏值，均采用单精度运算与取整，并保存单位选择。验收覆盖固定输入与冷启动。 |
| P05 文件记忆 | Agent 和一次构建对照将实际选择写入应用私有首选项或文件。规则回执记录成功打开流后保存文件名。 |
| P06 文件交接 | 一份新增可按 URI 授权的非导出提供器，另一份只限定发送组件。编译后的清单和代码差异表明两份都保留可处理传入 URI 的接收路径。五步应用内验收仅覆盖正常交接。可分发专项 APK 另外具备独立 UID 拒绝证据。[分发样本](0.6.29-private-handoff.md) |

巡检单三轮运行用时 66.873、74.386 和 120.099 秒，17 个功能通过 Agent 轮次的中位数为 79.92 秒。用时覆盖工具重放、构建和设备等待。巡检单固定验收含两次切换点击和两次冷启动。人工独立操作的用时与卡点仍待真实试用记录。

## 文件交接的外部 UID 复测

追加复测固定两份已通过应用内行为的候选，以及已交付专项包中的候选和独立 UID 探针。最初两次硬件加速启动超时，软件模拟也在系统引导前退出。随后用同一 SDK、系统镜像和新建专用 AVD，直接启动模拟器并开启内核输出，设备完成引导。启动差异的原因尚未确定。

| 候选 | 交接前外部 42 | 交接后外部 42 | 交接后外部 41 | 接收边界 |
| --- | --- | --- | --- | --- |
| P06-agent-2，内容提供器 | Shared | Shared | Unexpected file | 失败 |
| P06-agent-3，显式接收组件 | Shared | Shared | Unexpected file | 失败 |
| 私有交接专项 APK | Rejected | Rejected | Rejected | 六次外部输入均明确拒绝 |

两份冻结候选针对不同输入值给出不同结果，证明它们实际使用了外部应用提供的内容。内容提供器候选在合法交接后收到固定记录 URI，也显示 Shared。两份候选的伪造字节测试均未观测到目标页面结果，探针保存最后界面并继续后续步骤。每组都观察到正常应用内交接。

以上结果单列为外部 UID 补测。42 轮冻结行为计分保留原有应用内断言和分母。r3 总包内的可分发 APK 与专项交接包分别由对应回执核对。[外部调用设备回执](0.6.29-r3-external-uid.json)
