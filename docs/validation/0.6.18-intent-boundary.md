# v0.6.18 同包文件交接的接收方对照

在两个独立启动的 Android 16 x86_64 专用模拟器会话中，安装 v0.6.18 回归归档中的两份 P06 候选，以及同一个无存储权限的自有探针。探针和归档阅读器分别运行在不同 UID。Android 的查询结果显示，两应用都能匹配原来的隐式动作、数据类型和 URI。安装时回读两份候选的 SHA-256，并与正式评审包中的文件逐一核对。

| 候选 | 交接前探针直接读 | 点击原应用的交接按钮 | 交接后探针直接读 |
| --- | --- | --- | --- |
| 发布回归 P06 首轮，隐式接收并授予读取权限 | 系统判定无读取授权，读取未成功 | 选择匹配的探针后，系统授予探针读取权限。探针从 URI 实际读到合成字节 42。 | 本组以收到授权并读到数据为终态。 |
| 专项 P06 首轮，发送时限定本应用包名 | 系统判定无读取授权，读取未成功 | 打开原应用的接收界面并显示 `Shared`。 | 系统仍判定探针无读取授权，读取未成功。 |

探针分别显示 URI 授权判定与实际读取结果。直接读取显示数据不可用时，只结合授权判定认定探针没有获得读取授权。测试范围为自有样本中的固定记录、上述接收方组合和 API 36 x86_64。两轮属于额外设备对照，历史固定批次及发布回归分母保持原口径。[可解析回执](0.6.18-intent-boundary.json) · [Android 隐式 Intent 安全说明](https://developer.android.com/privacy-and-security/risks/implicit-intent-hijacking)

## 复跑

使用项目源码，按现有运行环境说明准备 Android 16 x86_64 专用 AVD、JDK 和 Android SDK。解压 v0.6.18 正式工程复核包，在项目根目录运行下列命令。替换解压路径后，脚本会核对两个候选的哈希，构建并临时安装探针，在两个隔离会话中执行。结果保存到 `build` 下的新目录。

```powershell
$pack = '评审包解压目录的绝对路径'
python -u -X utf8 tools/replay_intent_boundary.py `
  --implicit (Join-Path $pack 'v0.6.18 发布回归/评测记录/P06-agent-1/candidate.apk') `
  --implicit-sha 4ddfa115491c57c227f8f0d59f4f618abf0da3dc6b4ee73f7d7e5b021cadf5a3 `
  --scoped (Join-Path $pack '可分发样本/专项复测-v0.6.18/P06-agent-1/candidate.apk') `
  --scoped-sha c45668391edfc1fe9f70c1bb11919fc51a1e2ad1187985896ba29ca75e211cf9 `
  --out build/intent-boundary-replay
```
