# v0.6.25 干净 Windows 首次准备预检

在此前从空白虚拟磁盘安装的 Windows Server 2022 虚拟机中，用同版便携 EXE 和新的独立应用存储启动工作台。Android 16 初始缺少 platform-tools、emulator、build-tools、系统镜像和 Java。未确认条款时提交首次准备请求返回 HTTP 400，五项缺失状态保持原样，下载任务未创建。模型关闭，虚拟机无网络。

使用同一份 Android Emulator 36.6.11 的 `emulator-check.exe` 对照宿主与虚拟机。Windows 11 宿主返回 0 并报告 WHPX 可用。VMware 客户机返回 3 并报告未提供虚拟化扩展，Windows 的 CPU 能力查询一致。该虚拟机中的实际首次下载和 Android 设备步骤待复核。当前 Android 行为验收仍对应已准备好模拟器的宿主环境。[Android Emulator 加速检查说明](https://developer.android.com/studio/run/emulator-acceleration) · [VMware 嵌套虚拟化说明](https://knowledge.broadcom.com/external/article/313547/)

检查首次准备入口时还发现，源码会把字符串 `"false"` 等非布尔值当作同意。后续源码已改为只接受 JSON 布尔值 `true`，无效或非对象的历史记录恢复为未确认。回归用例覆盖接口管理器、保存状态及准备函数，核对拒绝后无任务、无下载、无许可状态改写。此项修订的证据来自源码测试，已归档的 v0.6.25 EXE 回执独立保存。
