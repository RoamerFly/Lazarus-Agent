# v0.6.29 私有文件交接复核

在 v0.6.29 对应源码 `0e95b5f` 重放历史 Flash 完成的私有交接编辑。原 APK、历史结果和工具轨迹先核对身份。本次用同版工具链重新回编签名，唯一编辑的 Smali 文件与历史改动的 SHA-256 一致，实际模型调用为零。[历史试验](0.6.26-flash-private-handoff.md) · [留档编辑](recorded-edit-fixtures/P06-private-receiver.json)

修订候选用显式组件发起交接。接收页面先核对进程内令牌，再读取应用私有目录中的记录。应用内读取与接收端拒绝都由实际设备操作观察。原包的目标 SDK 为 22，新包为 24。静态复查未发现新增或移除的权限、组件或共享库。

| 验收 | Android 16 x86_64 结果 |
| --- | --- |
| 原包 | 默认安装失败 |
| 重建 APK | 签名构建成功，安装和启动通过，设备回读哈希一致 |
| 应用内交接 | 同版 EXE 独立通过 5 步，覆盖冷启动后再次读取 |
| 固定探针地址 | 合法交接前后各一次，接收端均显示 Rejected |
| 伪造字节 | 合法交接后一次，接收端显示 Rejected |
| 外部可读记录 | 匹配字节在合法交接前后各一次，另有一次不同字节。接收端均显示 Rejected |

外部测试核对探针 APK 的安装哈希、不同 UID 和每组测试中的合法应用内交接。固定探针地址沿用历史夹具。实际实现直接打开应用私有文件。外部记录测试使用另一应用自己的 ContentProvider。结论覆盖上述六次外部输入。此前 v0.6.29 Flash 续修的功能通过和接收端误接纳证据独立归档。[上一轮对照](0.6.29-flash-p06-guard.md)

专项复测包与 r2 评审包绑定同一份 EXE。Windows PowerShell 5.1 解包后核对 15 个登记文件及 APK 输入。用解出的候选和探针实际重跑，应用内再次通过 5 步，六次外部输入再次显示 Rejected。原始观察也用于修正校验器的节点格式兼容，内存元组与 JSON 数组现在按相同规则核对。包的两次构建逐字节一致。重算外层清单后，验证器仍拒绝了包含 Shared 的外部结果、相同 UID、错误设备回读哈希和缺失验收声明。[专项回执](0.6.29-private-handoff.json)

探针的 `--private-boundary` 退出状态与专项包审核现在共用判定。六次观察均要求目标应用明确显示 Rejected。仅观察到调用方报错、无法读取或内容不匹配时，该项证据不足。用同一判定重新审核已交付的专项 ZIP，留档的六次明确拒绝全部通过。[r3 候选改动复核](0.6.29-source-zip-candidate-review.md)

后续在专用 Android 16 x86_64 模拟器重新安装同一专项 APK 和同一探针，核对设备回读与两个独立 UID。两次设备复跑均完成正常交接，并明确拒绝全部六次外部输入。另行测试的两份冻结批次候选实际接纳外部可读数据。[追加设备回执](0.6.29-r3-external-uid.json)
