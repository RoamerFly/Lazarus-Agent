# v0.6.6 通用 APK Agent 实测

本轮移除了对话中针对页面方向的专用派发。模型直接选择 APK 工作区和设备工具。文件工具支持搜索、读取 smali 方法、按原文或行号修改、新建和恢复。构建回传失败原因，同轮可调整补丁重试。专用设备工具可读取界面、点击、输入和重启。对话保存候选与输入哈希，可在下一轮继承。

实测使用真实 DeepSeek Flash 和 Android 16 专用模拟器，通过工作台的修复对话上传 OI Notepad 1.3 并发起请求。此前未为字符计数或笔记模板实现专用工具。APK 补丁由模型使用通用工具生成。非思考模式曾在反复读取时耗尽执行限额。本轮复测使用 DeepSeek 思考模式，按[官方工具调用协议](https://api-docs.deepseek.com/guides/thinking_mode/#tool-calls)在同一请求链中保留模型上下文。

## 默认字符计数

需求为首次安装默认显示字符计数，且用户可在设置关闭。模型定位到偏好读取的 smali 默认参数和设置页的 XML 默认值，修改这两个文件，回编签名并安装至 API 36。测试记录显示输入 `hello` 后标题为 `[5] Create note`，设置页从 `Show character count in editor` 切换为 `Do not show character count in editor`，随后重新打开笔记时标题为 `Edit note`，正文仍为 `hello`。

对话下载件与设备回读哈希均为 `222dc69b9c9f0cf66a3889b54f4ffb5aa5bec3e456a39aa3e2863bdd59c8c146`。

## 基于候选继续添加三行模板

在同一任务中追加请求，要求新建笔记预填「事项：」「时间：」「备注：」三行，打开已有笔记保留正文。模型从上轮候选读取代码，定位到 `NoteEditor.onCreate` 的新建分支并修改 smali。候选输入哈希等于首轮下载件。设备测试中，新建页显示三行及字符数 11。输入 `TEST123` 后返回列表，再打开该条笔记，正文仍为 `TEST123` 加原模板，没有重复追加模板。

对话下载件与设备回读哈希均为 `a566efbf6b191ca7719620b74cc6fe9c96e31e9c470c136211c3123a57ad6240`。独立检查脚本根据界面节点断言两项功能效果，并核对 APK 哈希链。首轮模型修正了多次精确匹配失败后继续构建。编译失败后返修由回归测试覆盖。

本地完整证据位于忽略目录 `build/generic-agent-066/`，包括各轮对话、工具结果、文件差异和设备界面树。175 项单元测试通过，覆盖路径范围、修改前哈希、Windows 换行、构建失败回传、最新构建约束和 DeepSeek 连续工具协议。该样本的功能测试在 Android 16 模拟器完成。通用代码修改范围包括可解包的文本资源与 smali，原生机器码、不可解包格式与外部服务依赖需按实际证据评估。
