# USB 真机预览延迟优化

验证日期：2026-11-24。

用户报告真机预览约 1041 ms。连接 vivo V2415A（Android 16）后，旧版原始 `screencap` 每帧传输约 14 MB，实测 1031–1281 ms。手机熄屏时，`screenrecord` 在标准输出返回 `ERROR: INVALID_LAYER_STACK`；旧链路将该文本交给 OpenCV 流探测，反复等待超时，然后回到原始截图。亮屏但画面静止时，旧流探测同样可能等待完整超时并重启。

修复：切换 USB 设备时并行启动 H.264 流；首次取帧短暂等待正在启动的视频，避免立即执行一次完整截图。用内置 PyAV 直接解析帧，静止画面使用访问单元分隔符释放最后一帧，持续保持解码器和 USB 链路。页面仍按原有节奏只取最新 JPEG 帧，切换设备、断线或闲置时终止传输。视频不可用时改用 `screencap -p` 压缩截图，并对视频重试设置间隔。模拟器预览不变。

受控实测：熄屏时压缩截图约 500–531 ms；在真机上独立验证的新解码算法首帧约 391 ms。亮屏画面复杂时压缩截图仍可约 1 秒，实际交互以持续视频流为主。后续在最终工作台/EXE 上的真机稳态和点击响应，需要手机重新出现在 ADB 列表中才能验收。诊断和算法测试未安装 APK、未保存手机画面、未发送模型请求；仅为诊断短暂唤醒并恢复手机屏幕状态。

回归：`python -m unittest discover -s tests -q` 209 项通过；`node --test tests/*.test.cjs` 13 项通过。新增静止画面持续解码、静止后画面变化、熄屏错误快速退出、USB 压缩备用截图、首帧优先视频和预先启动流的测试。桌面包以清理开发者路径的受控 `--self-test` 检查 PyAV H.264 解码器和便携环境。
