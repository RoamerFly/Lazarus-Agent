# v0.6.29 文件交接续修与接收边界

这是一轮已见自有夹具的开发专项。按预先固定的 P06 原包、需求及五步验收进入同版工作台导入和对话接口。先重放 11 次历史工具调用。新版构建检查实际拒绝了没有限定接收方的 URI 授权，然后将失败信息交给 Flash。42 轮冻结批次单独计分。[固定试验计划](0.6.29-flash-p06-guard-plan.json)

首个模型请求因试验脚本生成的历史工具消息缺少类型字段而需要更正。工作台收到 HTTP 错误，未收到模型回复。修正后共收到 7 次 Flash 回复，连同首个失败请求达到 8 次总上限。供应方记录 87,238 个输入 token，其中 71,936 个命中缓存，输出 741 个 token。[接口字段](https://api-docs.deepseek.com/api/create-chat-completion/)

## 构建、启动与行为

Flash 将发送端 Intent 指向原接收组件，回编和签名成功。Android 16 安装回读与该候选一致，启动未进入目标页面。Flash 通过工作台设备工具读取崩溃缓冲区中的 `java.lang.VerifyError`，随后把发送方法的局部寄存器声明增至 3。总请求上限在下一次构建前结束对话，工作台未开放已验收下载。

使用已保存的工具参数离线重建最后的编辑，三个修改文件的前后哈希与留档一致。由同一便携 EXE 在 Android 16 x86_64 独立运行五步。原包无法安装，重建候选安装和启动通过，设备回读哈希一致，点击、读取、冷启动和再次交接共通过 5/5 步。这里的行为证据对应离线重建结果，真实模型对话只完成到最后一次编辑。

## 不同 UID 的可读记录

另一个自有探针应用在自己的 ContentProvider 提供两份可读记录，每份一个字节，值分别为 42 和 41。探针向原有接收页面发起显式请求。与前一阶段的伪造字节参数或不可读 URI 相比，这一检查直接覆盖接收端打开外部可读数据的路径。每轮核对设备安装回读、探针 APK 哈希、两个独立 UID，以及一次合法的应用内交接。

| 候选 | 外部 42，合法交接前 | 外部 42，合法交接后 | 外部 41，合法交接后 | 应用内交接 |
| --- | --- | --- | --- | --- |
| v0.6.29 留档显式组件对照 | Shared | Shared | Unexpected file | Shared |
| 本次 v0.6.29 续修后离线重建 | Shared | Shared | Unexpected file | Shared |
| v0.6.26 私有交接对照 | Rejected | Rejected | Rejected | Shared |

当前续修限制了发送端的接收组件。旧的接收页面仍会打开外部应用提供的 URI，并根据读到的字节返回界面结果。两个输入值验证了接收端实际使用外部内容。带接收端校验的历史对照保留应用内交接，并拒绝三次外部输入。当前续修候选归入功能通过、接收边界失败的开发证据。[分阶段回执](0.6.29-flash-p06-guard.json) · [私有交接对照来源](0.6.26-flash-private-handoff.md)

## 复跑

准备 v0.6.29 源码提交 `0e95b5f`、Android 16 x86_64 专用实验室和原 APK。以固定参数执行离线回编，再用同版 EXE 复测冻结协议中的 P06 五步。

    python -X utf8 tools/replay_agent_edit_trace.py <同版源码检出> <原APK> <工具轨迹> <同版源码检出>/build/p06-guard-replay --allow-unfinished
