# v0.6.28 旧版 OI 记事本复核标记试验

以原版 OI Notepad 1.3 的 APK 启动工作台对话流程，在一个任务中请求补齐 Android 16 安装兼容性，并在正文编辑器增加幂等的复核标记。验收事前固定为 16 步，覆盖两份正文、重复点击和冷启动。该试验属于单轮工程探测。

工作台使用 v0.6.28 对应源码 `cbd58ed`。导入、对话、状态及候选接口沿用应用路由，在本机测试客户端执行。试验仅给模型传输加了请求与用量上限。服务端报告 `deepseek-flash`，共 20 次请求和 20 份响应。记录输入 token 517,555，其中缓存命中 490,880，输出 token 9,956。

模型实际修改布局与编辑逻辑并完成一次签名构建。Android 16 x86_64 模拟器安装并启动成功，回读哈希与预检构建一致。首次进入出现应用自己的许可页，第一步无法找到「Add note」，功能验收为 0/16。Agent 随后发出设备操作，工作台因为预检后的设备上下文未衔接而拒绝操作。试验达到调用上限，没有生成可下载候选，也没有后续的独立 EXE 验收。

基于同一候选源码修复了预检与下一次设备操作的衔接。只有一次新预检实际回读出当前构建的安装哈希，才允许用它继续操作；重复读取历史预检仍保留设备上最后实际安装的对象。预检继续与最终独立验收分开。

修订源码用留档工具操作离线复跑同一任务。预检到达同一许可页，之后只读取前台界面，成功确认所读取的对象为刚预检的候选。复跑在许可页停止，本次实验没有导出 APK。该结果验证了通用设备工具的衔接，记事本复核标记的功能仍待完整验证。
