# v0.6.28 三类冻结反例的离线复核

使用同版便携 EXE，在 Android 16 API 36 x86_64 专用模拟器重放 P1C 固定反例。N01 与 N02 以未修改原包作为复测输入。N03 使用已签名的标题修改候选。

| 反例 | 安装 | 启动 | 功能及拒绝原因 |
| --- | --- | --- | --- |
| N01 仅有 MIPS 原生库 | 被拒绝 | 未运行 | Android 返回 `INSTALL_FAILED_NO_MATCHING_ABIS` |
| N02 要求恢复从未提供的校验码 | 通过 | 通过 | 固定断言找不到校验码，匹配数 0 |
| N03 同一界面的矛盾断言 | 通过 | 通过 | 首步查到标题，第二步要求同一标题不存在，断言失败 |

每个反例都得到独立验收的退出码 1 和 `incomplete`。评审脚本另外确认预期失败阶段、Android 版本、安装回读哈希或安装错误。打包校验器将用例和原包绑定到同版源码里的冻结清单。重新计算 ZIP 内哈希后，换成其他安装错误、改写 N02 固定断言或移除冻结范围仍被拒绝。

另用同版源码重放两段历史 Agent 工具决策。N01 对原包及重新签名的清单修改实验分别实际测试，两次安装均因 ABI 不匹配失败。轨迹恢复清单，进入 `blocked`，没有导出候选。N02 对三组关键词搜索均零命中，进入 `analysis`，构建次数为零。两段重放执行实际工具，工具选择和结束状态来自历史轨迹。本轮没有真实模型调用。

这组三个同版反例覆盖工程复跑。历史模型反例门槛另见 P1C 的六轮记录。
