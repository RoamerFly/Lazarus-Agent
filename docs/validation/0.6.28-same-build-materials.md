# v0.6.28 同版方案、演示与评审包

六页方案将历史 42 轮开发回归、当前离线重放和 Windows 环境准备分开列证。逐页渲染核对 A4 页面、版本、表格和页脚。51 秒演示使用同版源码工作台，提交自有巡检 APK 的路线保留需求，重放 14 次留档工具调用并实际构建、签名和验收。工作台导出的候选与 Android 16 模拟器回读的安装哈希一致。

四份跨应用样本在 Android 16 x86_64 共通过 38 个固定步骤。N03 先断言标题存在，再断言同一标题不存在，安装和启动通过后拒绝功能验收。评审包附四份样本、反例、演示 APK、源码、设备报告、编辑轨迹、便携 EXE 哈希和 Windows 空目录准备回执。

文件交接对照另包归档。既有修复候选通过应用内五步。保留 SDK 22 的纯回编包在安装阶段被拒绝，仅提升目标 SDK 的候选能安装和启动，交接行为仍失败。外部 UID 拒绝结果沿用 v0.6.26 专项原始证据。

解压后校验文件，并由同版 EXE 核对六份样本输入。随后在 Android 16 专用模拟器实际重跑演示 APK，十步行为通过，设备回读哈希与录制、导出记录一致。重新计算外层哈希后，校验器仍拒绝 Java 下载进度未达总量或演示记录换成异版 EXE 的归档。此次离线复测及录制调用真实模型零次。

r2 补入[评审操作与答辩提纲](0.6.28-reviewer-guide.md)和同版源码中的样本使用说明。除索引及校验元数据外，初版 41 个条目逐字节相同。解压后的六份输入再次通过校验。篡改样本使用说明并重算两层校验后，校验器仍按同版源码拒绝变体。

另行归档关闭模型后的归档阅读器修复。Android 16 六步包含冷启动，候选与安装回读哈希一致。[无模型修复](0.6.28-local-rule-archive.md)

从空白磁盘安装的 Windows 虚拟机另行通过两份输入校验、隔离安装和登录会话的原生工作台启动。三个环境各自的验收范围见[干净桌面复核](0.6.28-clean-desktop.md)。
