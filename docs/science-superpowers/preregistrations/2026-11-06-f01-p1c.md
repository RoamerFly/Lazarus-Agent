# F01 P1C 跨应用前瞻复验

本批保留既有的联合门槛。锁定前完成三项设备可行性核验。

- 已见归档阅读器通过行为预检正反例和独立验收。[行为预检](../../validation/agent-rehearsal-device.md)
- 精确受测实现使用真实 DeepSeek Flash 复现已见故障。Agent 自主调用兼容库声明和行为预检，一次构建完成六步独立验收。[系统库开发验证](../../validation/agent-platform-library.md)
- 新留出样本仅使用原包测试数字输入、结果显示和冷启动，七项通过。该核验没有调用模型或运行改造候选。[原包输入证据](../../validation/f01-p1c-input-feasibility.json)

APK 回编工具使用已校验的本地 Apktool，SHA-256 为 `66cf4524a4a45a7f56567d08b2c9b6ec237bcdd78cee69fd4a59c8a0243aeafa`。

## 预测与联合门槛

预测使用指定构建的 Agent 能在固定批次同时满足正例至少 15/18、主案例 P01 通过 3/3、反例明确拒绝 6/6 且错误验收 0/6，以及留出 P04 至少 2/3。任一条件不足即记为未达到门槛。每个正例的通过需要候选安装回读哈希相符、全部固定步骤通过，以及原包安装拒绝或未满足相同行为检查。

## 样本与流程

- 使用 `tools/f01-p1c-cases.json`。沿用 P1B 的五个已见正例和三个反例。留出 P04 是自制仓库温度卡，检查按输入换算和冷启动记住显示单位。此前仅编译、签名、静态检查以及执行原包输入流程的可行性核对。评测脚本只向模型提供导入的 APK 工作区、用户需求和验收步骤。
- 受测应用逻辑为开发提交 `1a7bbbeed8e2b75386f7d8b79f61bed091458440`。固定 Android 16 AOSP API 36 x86_64 专用模拟器（default 镜像修订 2）和官方兼容接口 `deepseek-flash`。响应模型名和可用指纹随计量记录。托管端模型版本可由服务商更新，复现时保留执行日期和响应信息。[DeepSeek 模型与计价](https://api-docs.deepseek.com/quick_start/pricing/)
- 固定 42 轮。六项正例分别运行 Agent 三次、无语义回编一次、已有离线规则一次及同模型一次构建一次，三项反例分别运行 Agent 两次。一次构建对照无设备反馈，首次构建后结束，由同一独立验收器检查候选。两组的差异代表整套工作流的差异。单项工具的独立因果效果需要单独设计对照。
- 最多执行预定轮次。已启动缺终态者保留分母，标为未观测。中断后只可继续尚未启动的轮次。没有观察到反例拒绝的轮次计入反例分母。各用例内重复反映工具和模型运行波动。
- 执行 `python -X utf8 tools/run_f01_p1.py --protocol tools/f01-p1c-cases.json --out build/p1c --credential-file <本地凭据文件>`。用 `python -X utf8 tools/audit_f01_p1b.py . --batch p1c` 核对冻结输入、结果、候选 APK、独立验收和基准比较。

## 汇总与适用范围

按用例报告全部状态，分别呈现已见任务、留出任务和对照。保留实际构建次数、耗时、目标系统与 ABI、模型用量。按固定公开单价估算用量可核对的费用区间。缺失计量按缺失处理。联合门槛之外描述一次构建对照成败、预检是否找到真实失败以及 Agent 是否据此再构建。保留每个通过候选的差异核对，尤其检查温度计算是否依赖真实输入、持久化是否只保存显示单位。行为通过数与人工差异审查结果分别记录。

批次内不改用例、输入、工具预算或计分。追加的调试、工程复跑或其他设备记录单列。本批结果只描述所测应用、操作和环境。
