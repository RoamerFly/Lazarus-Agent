# F01 P1B 跨应用前瞻复验

本计划冻结第二批评测。第一批及 v0.6.8 开发回归分别保留，继续用原分母。预备提交为 `3522aa98c5a9e380edae2b8204b7bd0211e36c78`，受测应用逻辑为 v0.6.15 的发布提交 `781fb4bc035fff44f7c20d250636424c04c2a4ed`。

## 预测和判断条件

预期通用 Agent 能在这组预先选定的 APK 任务中达到原定交付门槛，并在此前未用于调优的雨伞借还点上至少通过两轮。整组通过要求同时满足四项：正例至少 15/18，巡检单 P01 为 3/3，反例明确拒绝 6/6 且错误验收为 0/6，留出样本 P04 至少 2/3。任一条件未满足，整组记为未达到门槛。第三项中缺少拒绝证据的轮次计入六轮分母。

## 样本和实施

- 采用 `tools/f01-p1b-cases.json`。沿用第一批 P01、P02、P03、P05、P06 和 N01–N03，按已见过的任务报告。P04 由原购物清单换为不同包名和实现的自制雨伞借还点，覆盖中文资源、加减计数、零下限和冷启动复位。冻结前只编译、签名和静态检查其原包与步骤，未运行 Agent 或查看候选。五项已见任务的重复证据和单一留出任务分别报告。
- 固定 DeepSeek Flash 和本项目配置的官方兼容端点，模型由服务商托管。保留响应模型名与可获得的指纹。使用本机隔离的 Android 16 AOSP API 36、x86_64、default 镜像修订 2，按同一评测运行器执行。已在类似自制 APK 上完成资源改造、计数、冷启动、一次构建及无模型对照，见第一批逐案报告和 v0.6.8 工程回归。新版 10 步独立验收已用既有 P01 候选本机复跑。
- 执行固定 42 轮。六项正例各三次 Agent，三项反例各两次 Agent。六项正例分别追加无语义改动回编、原有离线规则及同模型一次构建三种对照各一轮。每个导出候选用同一原包与固定步骤独立验收，核对安装回读哈希。基线安装拒绝或未达到同一行为断言才归因为改造通过。
- 从此文件首次提交的检出目录执行 `python -X utf8 tools/run_f01_p1.py --protocol tools/f01-p1b-cases.json --out build/p1b --credential-file <本地凭据文件>`，用 `python -X utf8 tools/summarize_f01_p1.py build/p1b --protocol tools/f01-p1b-cases.json` 汇总。凭据和原始运行文件保留在本机。

## 单位、对照与报告

统计单位为应用上的预定任务，重复执行反映同一任务的运行波动。采用一个联合通过门槛，不用显著性检验。对照按用例公布成败，描述同一任务的结果差异。记录构建次数、耗时、调用模型、已返回的用量和按汇总代码固定单价计算的费用区间，缺失计量保留为空值。比率仅描述本批任务。

计划轮数固定。已启动且缺终态的轮次保留在分母并标为未观测。中断后只执行尚未启动的轮次，不替换已运行或失败的轮次。完整报告同时列出原始冻结批次、开发回归和 P1B。观察结果后追加的任何调试、补跑或解释性切片单列。
