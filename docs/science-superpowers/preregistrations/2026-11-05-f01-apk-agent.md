# F01 P1 跨应用验收预注册

**Frozen at commit:** pending

2026 年 11 月 5 日。比较对象是通用 APK Agent、确定性的旧规则、无语义修改的回编和同模型单次构建。待测工程样本由团队自行编写。离线巡检单为留出样本，冻结前只构建并检查文件，未用于 Agent 调优或试跑。茶计时器上另外的状态文本任务用于验证运行器和独立验收。

## 假设与门槛

H0 为本次固定工程评测达不到预设交付门槛，或通用 Agent 未比相同模型的一次构建多完成用例。H1 为通用 Agent 至少通过 15/18 项正例轮次，巡检单达到 3/3，且 6/6 项反例均有明确拒绝证据。作为单独的对照判断，预期通用 Agent 至少有 5 个用例在 3 轮中通过 2 轮及以上，而且该用例数高于单次构建和旧规则各自通过的用例数。任何门槛未达成均如实报告；三类对照全量报告。

单位是预先定义的需求用例。重复轮次衡量同一应用任务的可重复性，正例的 18 次运行不当作独立应用，也不外推市场成功率。工程门槛使用计数，不作显著性检验，不增加亚组或事后择优。

## 固定协议

- 样本、提示词、断言与顺序采用同次冻结的 `tools/f01-p1-cases.json`。样本 APK 逐一锁定内容哈希。所有 Agent 轮次从原始 APK 及空会话启动。工具仅分析导入的 APK 和当前版本使用的私有实验室设备。设备为 Android API 36 x86_64 工作台 AVD，保留报告中的实际 ABI 列表和安装哈希。重新安装清理该应用上一轮的状态。
- 使用官方 DeepSeek `deepseek-flash` 接口，记录接口返回的型号与版本指纹。使用工作台当前模型循环和工具预算。通用组可自主构建、安装测试、读取界面及多次修订。对照组使用同一模型循环、工具预算和提示词，停在第一次实际构建结束，模型没有设备工具，也收不到构建结果反馈。独立验收使用同样的步骤。
- 原包和无修改回编均按同一断言执行。旧规则只走项目现有的安装门槛、系统 HTTP 兼容库或明确可识别的记录恢复规则；无对应现有规则的用例记录为未通过。规则用于恢复安装时，仍用完整功能断言检查恢复行为。
- 正例由独立验收器确认候选实际安装字节等于导出字节、启动可观察、固定断言全部通过，且原包在安装或固定行为上失败。仅安装启动、原包已满足、数据缺失或无候选均不得计正例通过。业务审查同时复核差异和保留实际处理的要求，对伪造成功、越权新增权限、跳过流程单列原因。
- 反例要求模型有真实响应，原包独立证明 ABI 不匹配或断言不成立，且无通过验收的候选。模型拒绝或交付未通过验收的试验候选都可以计为拒绝。接口不可用、程序异常或缺少验收记录计未观测。未观测轮次仍计入计划分母。
- 固定 6 个正例各 3 次、3 个反例各 2 次、正例各 3 种对照一次，共 42 轮。整个运行允许按固定用例组分批启动。已创建轮次目录不会覆盖重试。保留中断目录和失败结果。重复执行、补丁修复后的数据及额外测试与本次数据分列。
- 按轮记录回编次数、耗时、候选与设备状态、模型响应计量。计费采用响应的缓存命中、未命中及输出量，按 DeepSeek 公开闲时与峰时给出估计区间；没有完整计量时留空。计价页 [DeepSeek API 定价](https://api-docs.deepseek.com/quick_start/pricing/)。
- 正例在自动报告后按同一标准核查每个通过候选的差异。原包 SHA、目标 APK SHA、设备回读 SHA、独立日志与程序版本对应。若自动与差异核查不一致，自动计数保留并另列审查扣减。最终验收用扣减后的计数。
