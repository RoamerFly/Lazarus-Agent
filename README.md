# Lazarus Agent

Windows 桌面版「遗留软件复活智能体」。导入旧 APK，选择 Android 14、15 或 16，在隔离模拟器中安装、运行并验证修复结果。复测问题、截图、可重复操作和独立 APK 版本保存在本机。

## 按需求改造 APK

在“功能改造”中描述需求，选择原始 APK 或已验证的历史版本，并填写可复测的操作。当前提供两项能力。

| 需求 | 用户能核对的结果 |
|---|---|
| 记住上次打开的文件 | 选 B、强停并重开仍显示 B 正文，再切换到 A 重复一次。 |
| 新增简体中文 | 从包内扫描字符串并填写译文，切到中文检查界面，切回英语检查回退。还能点击中文按钮核对原有操作。 |

两类改造共用基准比对、无修改回编、签名、逐系统验收和版本下载。通过所有所选系统后可下载同一个独立安装包。自制示例均附源码，工作台执行时只读取导入的 APK。具体按钮和可复制的验收文字见[运行指南](运行指南.md)。

## 启动

从 [Releases](https://github.com/RoamerFly/Lazarus-Agent/releases) 下载 Lazarus-Agent.exe。桌面程序自带 Python 和 Web 服务，用 Microsoft Edge 的独立应用窗口显示界面。首次运行 APK 时，工作台检查 Android SDK、Java 和所选系统镜像，优先复用本机已有资源；需要联网时在你同意发布方条款后，从官方来源仅下载所缺组件。下载可取消，应用更新不会重新打包镜像。启动后点击“修复记录”可恢复历史任务。

设置 `REVIVER_SDK` 指向 Android SDK 根目录（包括 platform-tools、emulator、build-tools），按需设置 `REVIVER_BUILD_TOOLS`、`REVIVER_LAB`。默认本地端口为 8767，可通过 `REVIVER_PORT` 调整。任务数据位于 `%LOCALAPPDATA%\LegacyApkReviver\jobs`。初次使用前见[运行指南](运行指南.md)。若桌面版与旧网页服务使用同一端口，请先退出旧服务。

## 轻量安装与按需准备

普通用户只需下载一个 Windows 安装器或便携 ZIP。安装器和便携 ZIP 是两种交付方式，任选其一。选择目标 Android 版本后会检查环境；未选择的系统镜像不会随安装器下载。工具按发布方摘要校验、在暂存目录完整解压后发布，成功安装的压缩包会被移除。需要离线现场演示时，可提前在同一台设备上准备相应版本，或由 SDK 许可持有人按 [离线资源说明](OFFLINE_LAB.md) 自行组装可选资源包。

## 同一份 APK 的多版本验证

目标范围支持单选、多选，以及从工作台支持的最低版本验证到指定上限。当前修复目标为 Android 14、15、16（API 34、35、36）；Android 11 单独用于查看旧环境原貌。选择“兼容至 Android 15”会请求验证 Android 14 和 15。界面会列出实际请求的版本以及逐项结果。

同一个 APK 常能跨多个版本运行。工作台检查目标 SDK 安装门槛、原生库 ABI 和已知故障证据，优先在最高目标上尝试修复，再把同一文件送到其他目标进行默认安装、启动及配置的功能复测。只有各环境实际安装文件的 SHA-256 与候选文件相同，才将各行结果归到同一个产物。一个版本未通过时，可单独选择它重新诊断。降低清单里的最低版本无法补齐缺失的系统 API、处理器指令或第三方服务。

## 修复流程和模型

1. 导入完整的单个 APK，读取包名、签名、最低和目标 API，以及原生库信息。
2. 在专用目标环境里按系统默认策略试装、启动并执行指定操作，收集与该应用相关的错误。
3. 匹配有限的修复规则，包括安装门槛、旧系统共享库、丢弃有确切缺库证据的不完整 ABI，以及从包内恢复匹配的原生库。旧引擎机器码补丁只对校验过的特定二进制生效。
4. 生成候选时重新对齐、签名、安装并复测；报告区分启动验证、指定操作验证和用户真机反馈。抓不到有效证据或没有适用规则时，返回失败或限制原因。

默认使用本地规则。要启用模型，在工作台顶部打开 **模型配置**，填写兼容 Chat Completions 的接口根地址（例如本机的 `http://127.0.0.1:端口/v1`）、模型名称和服务商要求的 API Key。点击 **测试连接与工具调用**，勾选 **修复时允许调用该模型** 并保存。测试使用未保存的表单，只检查服务是否支持函数调用。Windows 用当前用户的 DPAPI 加密保存密钥，更换地址或模型需重新填写。进程环境中的 `REVIVER_MODEL_URL` 与 `REVIVER_MODEL` 同时存在时优先生效，配套密钥为 `REVIVER_MODEL_KEY`。

修复时，模型可以分轮读取清单、APK 结构和故障摘要。遇到未知缺失类，还能要求工作台在当前模拟器的系统共享库中查找实际定义该类的 JAR。找到唯一匹配时才开放相应的清单修复。若首次修复解决了安装门槛，又暴露出缺类错误，工作台可以从原包组合两项修改后重新签名、复测。任务诊断会列出采用的工具和证据。每次诊断最多四轮、八次工具调用。端点超时、工具不受支持或动作越界时会回退到本地规则。

模型收到的内容包括 SDK、ABI、所缺类或库的名称和分类后的故障。APK、原始日志、截图和签名密钥留在本机。问助手的外发开关独立于自动修复。已停服的后端和缺失的处理器机器码仍可能阻断修复，实际可用范围以各 Android 版本的安装、启动和指定操作验证为准。

## 反馈后继续修复

1. 导入 APK，选择目标系统，点击“修复并验证”。通过验证的文件进入版本列表，保留当时的验证等级。
2. 在手机上测试，选择对应版本，点击“真机可运行”，或描述问题并附一张 PNG/JPEG 截图。
3. 如能复现，请在“设置复现步骤”填写点击的控件和预期内容。也可以发送形如「点击“Open archived record”后应显示“Read OK: HTTP/1.1”」的消息。
4. 点击“继续修复”。工作台依据本轮运行证据选择已实现的规则。通过验证且内容变化时新增版本；相同哈希会沿用原版本。截图作为本机反馈记录，当前规则引擎使用可观测的安装、启动、控件和运行时证据进行判断。

代码仓库包含团队自制测试 APK。第三方商业游戏、实验室虚拟机、私有签名密钥和用户对话不入库。《环太平洋》的完整游戏交互复核需要事先配对的 ARM 实验室和本地参考画面；可通过 `REVIVER_GAME_REFERENCES` 指定参考目录。原开发机的验证范围见[阶段进度](阶段进度.md)。

## 开发和打包

```powershell
.\start_workbench.ps1
# 构建单文件 Windows 程序
.\build_desktop.ps1
```

输出路径为 `dist\Lazarus-Agent.exe`。源码运行与桌面程序共用工作台 API 和本地任务格式。
