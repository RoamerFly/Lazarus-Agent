# Lazarus Agent

Windows 桌面版「遗留软件复活智能体」。导入旧 APK，选择 Android 14、15 或 16，在隔离模拟器中安装、运行并验证修复结果。复测问题、截图、可重复操作和独立 APK 版本保存在本机。

## 按需求改造 APK

启用模型后，在修复对话描述改造需求。Agent 可以搜索和读取 APK 中的清单、代码和资源，修改后回编签名，根据错误和测试反馈继续迭代。离线规则仍可处理已经支持的兼容问题。

修复对话共用需求与反馈入口。语言修改是资源工具的一种，例如输入“汉化成中文”会生成签名候选 APK。工作台可识别普通 Android 字符串，以及 Unity 4 旧版 NGUI 的英文键值语言表和同文件材质引用的 RGBA4444 位图字库，资源可以位于 APK 或内嵌的单个 ZIP 格式 OBB 中。Unity 适配器替换英文语言槽，Android 资源适配器补充简体中文资源。对使用 Java 索引文本表的游戏，也能自动识别英文语言目录，重写字符串及其偏移、更新缓存版本，并给 GHL 位图字库补字。普通 Android 界面译文在简体中文语言环境生效。默认先用已有译文。词库未命中的英文会交给本机 OPUS-MT 模型翻译，首次使用下载约 67 MiB，后续可离线运行。在“模型配置”启用服务后，聊天任务会读取最新配置并使用相应接口，不需要语言功能专用的开关。

工作台还会查找编译进程序且明确标注语种的双语条目，并在独立的菜单、按钮或图集图片上用 OCR 定位文字、清除原字、绘制中文。异形美术字可用按图片指纹匹配的校对区域纠正。图片格式、识别置信度和字体会影响覆盖率。对话分别列出模型补译、图片重绘和游戏语言表覆盖数，并提供签名 APK。英译中权重使用 Argos 的 OPUS-MT en→zh 1.9（Jörg Tiedemann、Santhosh Thottingal，CC BY 4.0），下载后校验 SHA-256。汉化候选需另行验证目标设备与游戏画面。

功能验收按所选系统逐项执行。全部通过后可下载同一个独立安装包。自制示例均附源码，工作台执行时只读取导入的 APK。可按[运行指南](运行指南.md)填写验收步骤，或直接下载[已验证的 APK](fixtures/verified)对照体验。早期规则样本的系统版本、安装哈希与操作结果见[验收报告](docs/validation/0.4.0-modifications.json)。

## 启动

“模型配置”提供 DeepSeek、OpenAI 和自定义兼容接口。选择预设可填入地址与模型名称，所有字段仍可修改。填写对应密钥、启用并保存后生效。更换服务会清除尚未保存的草稿密钥；已保存密钥仍按接口与模型绑定。

启用模型后，修复对话进入通用 Agent 流程。模型根据需求和 APK 内容自行制定步骤，可以列文件、搜索和读取代码与资源、精确修改或创建文件、回编签名、查看错误并继续修改。Manifest、smali、资源和 assets 共用这些工具。已有批量汉化处理也作为工具供模型按需调用。工具具备目录、大小、调用次数和构建次数限制。模型可分析开放需求，实现范围取决于 APK 内容、可用工具和验证结果。

对话默认基于最新候选继续，选择历史版本后可从对应版本修改。上一轮对话摘要会进入上下文。每轮保留工具结果、文件差异和输入输出哈希。工作台已有目标环境时，模型还能自行安装候选、读取界面、点击控件、输入测试文本和冷启动。构建通过、安装启动和功能验收分别记录，下载的候选请继续在目标手机复测。

在「复现步骤」填写点击控件和预期结果后发送需求，工作台会独立安装基准包与候选包，按提交时的步骤逐系统复测。多步验收可逐行填写 `点击 | 控件`、`出现 | 预期文字` 或 `冷启动` 等操作。全部目标通过时提供「下载已验收 APK」。未通过时仍可下载试验候选和报告。报告保留两份文件的哈希、安装及操作结果，并列出清单声明和签名的变化。基准也通过时会单独标明。

下载验收报告后，可按[运行指南](运行指南.md#复测已生成的候选)使用桌面程序执行离线复测。复测使用报告里的步骤，核对基准 APK 和候选 APK 的文件哈希，再在专用设备安装运行。

从 [Releases](https://github.com/RoamerFly/Lazarus-Agent/releases) 下载 setup.exe 安装器，或下载 portable.zip 并解压后打开其中的 Lazarus-Agent.exe。桌面程序自带 Python 和 Web 服务，使用内嵌 WebView2 显示独立桌面窗口。重复启动会激活已有窗口。系统需要 Microsoft Edge WebView2 Runtime，缺少时程序会显示官方下载地址。首次运行 APK 时，工作台检查 Android SDK、Java 和所选系统镜像，优先复用本机已有资源；需要联网时在你同意发布方条款后，从官方来源仅下载所缺组件。下载可取消，应用更新不会重新打包镜像。启动后点击“修复记录”可恢复历史任务。

设置 `REVIVER_SDK` 指向 Android SDK 根目录（包括 platform-tools、emulator、build-tools），按需设置 `REVIVER_BUILD_TOOLS`、`REVIVER_LAB`。默认本地端口为 8767，可通过 `REVIVER_PORT` 调整。任务数据位于 `%LOCALAPPDATA%\LegacyApkReviver\jobs`。初次使用前见[运行指南](运行指南.md)。若桌面版与旧网页服务使用同一端口，请先退出旧服务。

## 轻量安装与按需准备

普通用户只需下载一个 Windows 安装器或便携 ZIP。安装器和便携 ZIP 是两种交付方式，任选其一。选择目标 Android 版本后会检查环境；未选择的系统镜像不会随安装器下载。工具按发布方摘要校验、在暂存目录完整解压后发布，成功安装的压缩包会被移除。需要离线现场演示时，可提前在同一台设备上准备相应版本，或由 SDK 许可持有人按 [离线资源说明](OFFLINE_LAB.md) 自行组装可选资源包。

## 同一份 APK 的多版本验证

目标范围支持单选、多选，以及从工作台支持的最低版本验证到指定上限。当前修复目标为 Android 14、15、16（API 34、35、36）；Android 11 单独用于查看旧环境原貌。选择“兼容至 Android 15”会请求验证 Android 14 和 15。界面会列出实际请求的版本以及逐项结果。

同一个 APK 常能跨多个版本运行。工作台检查目标 SDK 安装门槛、原生库 ABI 和已知故障证据，优先在最高目标上尝试修复，再把同一文件送到其他目标进行默认安装、启动及配置的功能复测。只有各环境实际安装文件的 SHA-256 与候选文件相同，才将各行结果归到同一个产物。一个版本未通过时，可单独选择它重新诊断。降低清单里的最低版本无法补齐缺失的系统 API、处理器指令或第三方服务。

## 修复流程和模型

1. 导入完整的单个 APK，读取包名、签名、最低和目标 API，以及原生库信息。
2. 在专用目标环境里按系统默认策略试装、启动并执行指定操作，收集与该应用相关的错误。
3. 匹配有限的修复规则，包括安装门槛、旧系统共享库、丢弃有确切缺库证据的不完整 ABI，以及从包内恢复匹配的原生库。旧引擎机器码补丁只对校验过的特定二进制生效。
4. 生成候选时重新对齐、签名、安装并复测；报告区分启动验证、指定操作验证和用户真机反馈。抓不到有效证据或没有适用规则时，返回失败或限制原因。

默认使用本地规则。要启用模型，在工作台顶部打开 **模型配置**，填写兼容 Chat Completions 的接口根地址（例如本机的 `http://127.0.0.1:端口/v1`）、模型名称和服务商要求的 API Key。点击 **测试连接与工具调用**，勾选 **修复时允许调用该模型** 并保存。测试使用未保存的表单，只检查服务是否支持函数调用。Windows 用当前用户的 DPAPI 加密保存密钥，更换地址或模型需重新填写。进程环境中的 `REVIVER_MODEL_URL` 与 `REVIVER_MODEL` 同时存在时优先生效，配套密钥为 `REVIVER_MODEL_KEY`。

修复时，模型可以分轮读取清单、APK 结构和故障摘要。遇到未知缺失类，还能要求工作台在当前模拟器的系统共享库中查找实际定义该类的 JAR。找到唯一匹配时才开放相应的清单修复。若首次修复解决了安装门槛，又暴露出缺类错误，工作台可以从原包组合两项修改后重新签名、复测。任务诊断会列出采用的工具和证据。每次诊断最多四轮、八次工具调用。端点超时、工具不受支持或动作越界时会回退到本地规则。

模型按任务接收必要的信息。兼容修复会发送 SDK、ABI、所缺类或库的名称和分类后的故障。修复对话会发送需求、近期对话，以及模型主动读取的 APK 代码、资源文本、工具错误和专用测试设备界面文字。完整 APK、截图和签名密钥保存在本机。问助手的外发开关独立于自动修复。已停服的后端和缺失的处理器机器码仍可能阻断修复，实际可用范围以各 Android 版本的安装、启动和指定操作验证为准。

## 反馈后继续修复

1. 导入 APK，选择目标系统，点击“修复并验证”。通过验证的文件进入版本列表，保留当时的验证等级。
2. 在手机上测试，选择对应版本，点击“真机可运行”，或描述问题并附一张 PNG/JPEG 截图。
3. 如能复现，请在“设置复现步骤”填写点击的控件和预期内容。也可以发送形如「点击“Open archived record”后应显示“Read OK: HTTP/1.1”」的消息。
4. 对功能改造，启用模型后在修复对话描述问题或新需求，选择对应候选再发送，Agent 会读取实际代码、工具反馈并继续修改。“继续修复”按钮用于已有兼容规则的重试。截图作为本机反馈记录；规则使用可观测的安装、启动、控件和运行时证据，通用 Agent 根据对话与工具读取结果执行。

代码仓库包含团队自制测试 APK。第三方商业游戏、实验室虚拟机、私有签名密钥和用户对话不入库。《环太平洋》的完整游戏交互复核需要事先配对的 ARM 实验室和本地参考画面；可通过 `REVIVER_GAME_REFERENCES` 指定参考目录。原开发机的验证范围见[阶段进度](阶段进度.md)。

## 开发和打包

```powershell
.\start_workbench.ps1
# 构建单文件 Windows 程序
.\build_desktop.ps1
```

输出路径为 `dist\Lazarus-Agent.exe`。源码运行与桌面程序共用工作台 API 和本地任务格式。
